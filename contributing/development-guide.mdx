## Prerequisites

Before you begin, ensure you have the following installed:

- **Node.js** (v18 or higher recommended)
- **Package Manager**: npm, yarn, or pnpm
- **Git** for version control

## Technology Stack

Subflow is built with:

- **Next.js 16** - React framework with App Router
- **TypeScript** - Type-safe JavaScript
- **Tailwind CSS v4** - Utility-first CSS framework
- **shadcn/ui** - Re-usable component library
- **Clerk** - Authentication and user management
- **MongoDB** - NoSQL database with Mongoose ODM
- **exchangerate.host** - Real-time currency exchange API

## Getting Started

<Steps>
  <Step title="Clone the repository">
    Clone the Subflow repository to your local machine:

    ```bash
    git clone https://github.com/ridemountainpig/subflow.git
    cd subflow
    ```
  </Step>

  <Step title="Install dependencies">
    Install the project dependencies using your preferred package manager:

    <CodeGroup>
      ```bash npm
      npm install
      ```

      ```bash yarn
      yarn install
      ```

      ```bash pnpm
      pnpm install
      ```
    </CodeGroup>
  </Step>

  <Step title="Set up environment variables">
    Create a `.env.local` file in the root directory with the following variables:

    ```env .env.local
    # Clerk Authentication (Required)
    NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=your_publishable_key
    CLERK_SECRET_KEY=your_secret_key
    CLERK_WEBHOOK_SIGNING_SECRET=your_webhook_secret  # Optional
    NEXT_PUBLIC_CLERK_SIGN_IN_URL=/login
    NEXT_PUBLIC_CLERK_SIGN_IN_FORCE_REDIRECT_URL=/subscription
    NEXT_PUBLIC_CLERK_SIGN_UP_FORCE_REDIRECT_URL=/subscription

    # MongoDB (Required)
    MONGODB_URI=your_mongodb_connection_string

    # Exchange Rate API (Required)
    EXCHANGERATE_HOST_API_KEY=your_api_key
    ```
  </Step>

  <Step title="Configure required services">
    ### Clerk Authentication

    1. Sign up at [clerk.com](https://clerk.com)
    2. Create a new application
    3. Copy the publishable key and secret key to your `.env.local` file
    4. (Optional) Set up webhooks and add the webhook signing secret

    ### MongoDB Database

    Choose one of the following options:

    <Tabs>
      <Tab title="MongoDB Atlas (Cloud)">
        1. Create a free account at [MongoDB Atlas](https://www.mongodb.com/atlas)
        2. Create a new cluster
        3. Set up database access and network access
        4. Get your connection string and add it to `.env.local`
      </Tab>

      <Tab title="Zeabur (Recommended)">
        1. Deploy using the [Zeabur MongoDB Template](https://zeabur.com/templates/KXL04P)
        2. Copy the connection string to your `.env.local` file
      </Tab>

      <Tab title="Local MongoDB">
        1. Install MongoDB locally
        2. Start the MongoDB service
        3. Use `mongodb://localhost:27017` as your connection string
      </Tab>
    </Tabs>

    <Note>
      The database name will be automatically handled by the application code.
    </Note>

    ### Exchange Rate API

    1. Visit [exchangerate.host](https://exchangerate.host)
    2. Sign up for a free API key
    3. Add the API key to your `.env.local` file
  </Step>

  <Step title="Start the development server">
    Run the development server:

    <CodeGroup>
      ```bash npm
      npm run dev
      ```

      ```bash yarn
      yarn dev
      ```

      ```bash pnpm
      pnpm dev
      ```
    </CodeGroup>

    Open [http://localhost:3000](http://localhost:3000) in your browser to view the application.
  </Step>
</Steps>

## Available Scripts

Here are the npm scripts available in the project:

| Script | Command | Description |
|--------|---------|-------------|
| `dev` | `next dev` | Start the development server on port 3000 |
| `build` | `next build` | Build the production application |
| `start` | `next start` | Start the production server |
| `lint` | `eslint` | Run ESLint to check for code quality issues |
| `format` | `prettier --write .` | Format all files using Prettier |

## Development Workflow

### Code Style

Subflow uses ESLint and Prettier to maintain code quality and consistency.

<AccordionGroup>
  <Accordion title="ESLint Configuration">
    The project uses Next.js ESLint configurations:

    - `eslint-config-next/core-web-vitals` - Core Web Vitals rules
    - `eslint-config-next/typescript` - TypeScript-specific rules

    Ignored directories:
    - `.next/**`
    - `out/**`
    - `build/**`
    - `next-env.d.ts`
  </Accordion>

  <Accordion title="Prettier Configuration">
    Code formatting rules:

    ```json
    {
      "tabWidth": 4,
      "semi": true,
      "endOfLine": "auto",
      "plugins": ["prettier-plugin-tailwindcss"]
    }
    ```

    The project uses 4-space indentation and includes automatic Tailwind CSS class sorting.
  </Accordion>
</AccordionGroup>

## TypeScript Configuration

The project uses TypeScript with strict mode enabled. Key compiler options:

- **Target**: ES2017
- **Module Resolution**: Bundler (Next.js optimized)
- **Strict Mode**: Enabled for type safety
- **Path Aliases**: `@/*` maps to the root directory
- **JSX**: react-jsx

## Project Structure

Subflow follows the Next.js App Router structure:

```
subflow/
├── app/              # Next.js App Router pages and API routes
├── components/       # React components
├── lib/              # Utility functions and configurations
├── public/           # Static assets
├── types/            # TypeScript type definitions
└── .env.local        # Environment variables (not committed)
```

<Tip>
  Use the `@/` alias to import from the root directory, e.g., `import { Button } from "@/components/ui/button"`
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Port already in use">
    If port 3000 is already in use, you can specify a different port:

    ```bash
    PORT=3001 npm run dev
    ```
  </Accordion>

  <Accordion title="Environment variables not loading">
    - Ensure `.env.local` is in the root directory
    - Restart the development server after changing environment variables
    - Check that variable names are exactly as specified (case-sensitive)
  </Accordion>

  <Accordion title="MongoDB connection issues">
    - Verify your connection string format
    - Check network access settings in MongoDB Atlas
    - Ensure your IP address is whitelisted
    - Verify database user credentials
  </Accordion>

  <Accordion title="Clerk authentication errors">
    - Verify API keys are correctly copied
    - Check that redirect URLs match your configuration
    - Ensure the Clerk application is properly configured
  </Accordion>
</AccordionGroup>
